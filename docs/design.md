# 設計

`requirements.md` の要件をどう実現するかを定める。

## 実行環境

Expo（React Native / TypeScript）で実装し、Expo Go から起動する。

動作確認の手段が Expo Go に限られるため、Expo Go に同梱されているモジュールだけで
組み立てられる構成を選ぶ。

| 用途 | 採用 |
| :-- | :-- |
| SDK | Expo SDK 57 |
| 画面遷移 | expo-router |
| 加速度・重力 | expo-sensors の DeviceMotion |
| 位置情報 | expo-location |
| 永続化 | expo-sqlite |
| 地図 | react-native-maps |
| 図形描画 | react-native-svg |
| 画面の消灯抑止 | expo-keep-awake |

いずれも Expo Go に同梱されており、追加のビルドなしに動く。

## 座標系と荷重の定義

### 車両座標系

右手系で定義する。

- `forward`: 車両の前方
- `right`: 車両の右方
- `up`: 鉛直上向き（重力の逆向き）
- `right = forward × up`

### 荷重ベクトル

**荷重は加速度の逆向き**である。表示するのはすべて荷重ベクトル `load = -a` とする。

| 運転操作 | 車両の加速度 | 荷重の向き |
| :-- | :-- | :-- |
| ブレーキ | 後ろ | **前** |
| 加速 | 前 | **後ろ** |
| 右コーナー | 右 | **左** |
| 左コーナー | 左 | **右** |

G-G ダイアグラムは縦軸の上を「前荷重」、横軸の右を「右荷重」とする。
ブレーキで上、加速で下、右コーナーで左に軌跡が伸びる。

### デバイス座標系からの変換

DeviceMotion が返す `acceleration`（重力を除いたユーザー加速度、m/s²）に、
キャリブレーションで得た回転行列を適用して車両座標系の加速度を得る。

端末は車体に固定されているため、この回転行列は走行中を通じて一定である。

## キャリブレーション

2 段階で行い、どちらも条件を満たした時点で自動的に次へ進む。運転中の操作を要求しない。

### 静止フェーズ — 重力方向の取得

停車状態で `accelerationIncludingGravity` を集める。
ばらつきが十分小さい状態が数秒続いたら、その平均を重力ベクトルとする。

iOS では重力は下向きに出る（画面を上にして水平に置くと z ≈ -9.81 m/s²）。
したがって `up = -normalize(重力ベクトルの平均)` となる。

### 加速フェーズ — 前方向の確定

「まっすぐ加速してください」と促し、ユーザー加速度を監視する。
直近 1 秒の水平成分をならした値が 0.5 m/s² 以上あり、かつ向きが動いていなければ、
その平均方向を `forward` とする。

**時速 10 km まで 10 m ほど、まっすぐゆっくり進むだけで成立することを狙う。**
広い道や長い直線を必要とすると、走り出す前の準備が重くなる。
10 m で時速 10 km に達する等加速度は 0.39 m/s² であり、発進の立ち上がりはこれより強い。
判定窓 1 秒・閾値 0.5 m/s² は、この動きで無理なく満たせる大きさである。

判定はサンプル 1 つずつではなく、ならした値に対して行う。
走行中は路面の凹凸やセンサーのノイズが 1 サンプルごとに乗るため、
サンプルすべてに閾値を課すと、まっすぐ加速していても外れ値 1 つで不成立になる。

向きが動いていないことは、判定窓の前半と後半それぞれの平均方向のずれで測り、
30 度以内であることを求める。平均どうしの比較なのでノイズは打ち消し合い、
曲がりながらの加速のように向きが一方向へ動いていく場合だけを弾ける。

閾値を低くすると、加速の向きに対するノイズの割合が増え、`forward` の精度は落ちる。
それでも低く取るのは、精度の最後の担い手を次の「確認」の段階に置いているためである。
向きが合っているかどうかは、機械の判定ではなくユーザーの目で確かめる。

減速を「前」と取り違える恐れは小さい。判定は静止フェーズの直後、
つまり停車状態から動き出したところで行う。停止状態から減速は起こらず、
発進の加速が先に条件を満たすため。

加速が弱い、あるいは向きが動いている場合は、代替値で先に進めず明示的にやり直しを求める。
ここで妥協した値を採ると、以降の記録がすべて無意味になるため。

画面には現在の水平加速度を表示する。何をどれだけ強く行えばよいかが分からないまま
待たされることを避けるため。

### 確認

キャリブレーション直後に、荷重の向きをその場で確かめる画面を出す。
荷重ベクトルを矢印で実時間表示し、次の 2 つを確かめるよう案内する。

- 軽くブレーキを踏むと、矢印が前を向く
- 右へ曲がると、矢印が左を向く

前後だけの確認では足りない。重力の向きを取り違えると、前後は正しいまま左右だけが入れ替わるため、
ブレーキの確認だけでは気づけない。

## 坂道での重力の扱い

**車体のピッチ・ロールに対する補正は行わない。**

勾配による重力の漏れ込みは、DeviceMotion が返す `acceleration` の時点で既に取り除かれている。
iOS は加速度計・ジャイロ・地磁気を統合して重力成分を推定し、それを差し引いた値を返すため、
坂道でも純粋な運動加速度が得られる。

残る誤差は、サスペンションの沈み込みやロールによって車体が路面に対して傾く分である。
数度の範囲に収まり、これを補正するにはサスペンションの特性を入力させる必要がある。
得られる精度に対して要求が重すぎるため、補正しない。

## データ量とサンプリング

| 項目 | 値 | 理由 |
| :-- | :-- | :-- |
| 加速度 | 50 Hz | G-G 軌跡の滑らかさが判別できる。これ以上上げても軌跡の見え方は変わらない |
| 位置情報 | 1 Hz | ルート描画と距離計算に十分 |

加速度はセンサーのコールバックごとに保存せず、メモリ上のバッファへ積み、
数秒ごとにまとめて 1 トランザクションで SQLite へ書き込む。

1 時間の走行で加速度は 18 万件。時刻で索引を張り、
G-G ダイアグラムの表示時は選択点の前後数秒だけを範囲で取り出す。
全件をメモリに載せる処理は設けない。

## 記録は前面のみ

Expo Go はバックグラウンドでの位置情報取得に対応していない。
記録中はアプリを前面に置いたまま使う。画面の消灯は expo-keep-awake で抑止する。
