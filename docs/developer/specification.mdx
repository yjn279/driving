## この文書の構成

記述を 4 つの階層に分けています。上の階層が下の階層の拠り所になります。

| 階層 | 何を書くか | 接頭辞 |
| :-- | :-- | :-- |
| 1. 方針 | 判断の拠り所。個々の仕様が割れたときはここへ戻る | `PHI` |
| 2. 仕様 | 何をどう作るか。センサーから画面までのデータの流れの順に並べる | `SNS` `CAL` `CRD` `REC` `VIS` |
| 3. 対象外 | 作らないと決めたもの | `SCP` |
| 4. 受け入れ基準 | 完成したと判断する条件 | `ACP` |

仕様はデータが通る順に並べています。

| 接頭辞 | 段階 | 扱うもの |
| :-- | :-- | :-- |
| `SNS` | 取得 | センサーから何を、どの速さで受け取るか |
| `CAL` | 較正 | 端末の向きを車両の向きへ対応づける |
| `CRD` | 変換 | 加速度を車両座標系の荷重へ直す |
| `REC` | 記録 | 何を、どう残すか |
| `VIS` | 可視化 | 何を、どう見せるか |

各項目の識別番号は[テスト内容](/developer/testing)から参照します。

## 1. 方針

このアプリの本質は「G の大きさ」ではなく、**G ベクトルの連続性を可視化すること** にあります。
荷重コントロールの上達とは、大きな G を出すことではなく、G を途切れさせずに繋ぐことです。
減速 G が抜けきる前に横 G へ、横 G が残っているうちに加速 G へ。

| ID | 方針 | 理由 |
| :-- | :-- | :-- |
| `PHI-01` | 最大 G やスコアを主役にしない | 大きな G を出すことは上達ではない。数値を競わせると、見るべきものから目が逸れる |
| `PHI-02` | 前後 G を縦軸・左右 G を横軸に取った G-G ダイアグラムの軌跡を可視化の中心に置く | 荷重が前後左右斜めのどこにかかっているかは、この 1 枚で過不足なく表せる |
| `PHI-03` | 軌跡が滑らかな円弧か、カクついているかを見せる | それがユーザーの見たい情報そのものである |

## 2. 仕様

### 2.1 取得（SNS）

実装は `app/record.tsx` にあります。

| ID | 仕様 | 理由 |
| :-- | :-- | :-- |
| `SNS-01` | 運動の入力には DeviceMotion の `acceleration`（重力を除いたユーザー加速度、m/s²）を使う | 重力の分離を iOS の統合処理に任せられる |
| `SNS-02` | 重力方向の取得には `accelerationIncludingGravity` を使う | 静止時にはこれがそのまま重力ベクトルになる |
| `SNS-03` | 加速度は 50 Hz で取得する | G-G 軌跡の滑らかさが判別できる。これ以上上げても軌跡の見え方は変わらない |
| `SNS-04` | 位置情報は 1 Hz で取得する | ルート描画と距離計算に十分 |

### 2.2 較正（CAL）

実装は `src/core/calibration.ts` と `app/record.tsx` にあります。

| ID | 仕様 | 理由 |
| :-- | :-- | :-- |
| `CAL-01` | 静止 → 加速 の 2 段階で行い、条件を満たした時点で自動的に次へ進む | 運転中にボタンを押させない |
| `CAL-02` | 静止の成立条件は、直近 2 秒間の 3 軸すべてで標準偏差が 0.15 m/s² 以下であること | アイドリングの振動は通し、車が動いている状態は通さない大きさ |
| `CAL-03` | あわせて、その 2 秒間の平均のノルムが 9.81 ± 0.5 m/s² に収まること | 重力以外の力が働いていないことの担保 |
| `CAL-04` | 静止フェーズの平均から `up = -normalize(重力ベクトルの平均)` を求める | 座標系の起点。ここが崩れると以降のすべての計算が意味を失う |
| `CAL-05` | 加速の成立条件は、直近 1 秒間の水平成分の平均が 0.5 m/s² 以上であること | 時速 10 km まで 10 m ほど進むだけで成立する大きさ。10 m で時速 10 km に達する等加速度は 0.39 m/s² で、発進の立ち上がりはこれより強い |
| `CAL-06` | あわせて、判定窓の前半と後半それぞれの平均方向のずれが 30 度以内であること | 曲がりながらの加速を弾く。平均どうしの比較なのでノイズは打ち消し合う |
| `CAL-07` | 判定はサンプル 1 つずつではなく、判定窓をならした値に対して行う | 走行中は路面の凹凸とセンサーのノイズが 1 サンプルごとに乗る。全サンプルに閾値を課すと、まっすぐ加速していても外れ値 1 つで不成立になる |
| `CAL-08` | 条件を満たさない場合は、推定値で先へ進めず、明示的にやり直しを求める | ここで妥協した値を採ると、以降の記録がすべて無意味になる |
| `CAL-09` | 確認の段階で、「ブレーキで矢印が前を向く」と「右コーナーで矢印が左を向く」の両方を確かめさせる | 前後だけでは足りない。重力の向きを取り違えると、前後は正しいまま左右だけが入れ替わるため、ブレーキの確認では気づけない |
| `CAL-10` | 較正の結果は保存・再利用せず、走行ごとに取り直す | 車載ホルダーへの取り付け角度は毎回わずかにずれる |
| `CAL-11` | 加速フェーズでは、判定に使っている現在の水平加速度を画面に表示する | 何をどれだけ強く行えばよいか分からないまま待たされることを避ける |

減速を「前」と取り違える恐れは小さいといえます。判定は静止フェーズの直後、つまり停車状態から
動き出したところで行うため、停止状態から減速は起こらず、発進の加速が先に条件を満たすからです。

### 2.3 変換（CRD）

実装は `src/core/vehicle-frame.ts` にあります。

| ID | 仕様 | 理由 |
| :-- | :-- | :-- |
| `CRD-01` | 車両座標系は右手系とする。`forward` は前方、`right` は右方、`up` は鉛直上向きで、`right = forward × up` | 3 軸の関係を 1 つの式で決めておくと、左右の取り違えが起きない |
| `CRD-02` | 荷重は加速度の逆向き（`load = -a`）とし、表示はすべて荷重ベクトルで行う | 運転者が体で感じるのは加速度ではなく、その反作用として体や車体にかかる荷重である |
| `CRD-07` | 端末座標系から車両座標系への回転行列は、走行中を通じて一定とする | 端末は車体に固定して使うため、両者の関係は走行中に変わらない |
| `CRD-08` | 坂道での車体のピッチ・ロールに対する補正は行わない | 勾配による重力の漏れ込みは `SNS-01` の時点で既に取り除かれている。iOS が加速度計・ジャイロ・地磁気を統合して重力成分を推定し、差し引いた値を返すため |

`CRD-08` に残る誤差は、サスペンションの沈み込みやロールによって車体が路面に対して傾く分です。
数度の範囲に収まり、これを補正するにはサスペンションの特性を入力させる必要があります。
得られる精度に対して要求が重すぎるため、補正しません。

#### 運転操作と荷重の向き

| ID | 運転操作 | 車両の加速度 | 荷重の向き |
| :-- | :-- | :-- | :-- |
| `CRD-03` | ブレーキ | 後ろ | **前** |
| `CRD-04` | 加速 | 前 | **後ろ** |
| `CRD-05` | 右コーナー | 右 | **左** |
| `CRD-06` | 左コーナー | 左 | **右** |

### 2.4 記録（REC）

実装は `src/db/schema.ts` ・ `src/core/distance.ts` ・ `app/record.tsx` にあります。

| ID | 表 | 列 |
| :-- | :-- | :-- |
| `REC-01` | `sessions` | `id` ・ `started_at` ・ `ended_at` ・ `duration_ms` ・ `distance_m` |
| `REC-02` | `locations` | `session_id` ・ `t` ・ `lat` ・ `lon` |
| `REC-03` | `accelerations` | `session_id` ・ `t` ・ `ax` ・ `ay` |

| ID | 仕様 | 理由 |
| :-- | :-- | :-- |
| `REC-04` | `locations` と `accelerations` に `(session_id, t)` の索引を張る | 時刻範囲での取り出しを速くする |
| `REC-05` | `session_id` は `sessions.id` への外部キーとし、セッションの削除で紐づく行も連鎖削除する | 削除の取りこぼしを仕組みで防ぐ |
| `REC-06` | 加速度はコールバックごとに保存せず、メモリ上のバッファへ積み、5 秒ごとに 1 トランザクションでまとめて書き込む | 書き込み回数を 250 分の 1 に抑えつつ、異常終了で失う量を 5 秒以内に留める |
| `REC-07` | 保存するのは車両座標系へ変換した後の `ax` ・ `ay` のみとし、上下方向は保存しない | G-G ダイアグラムは水平 2 軸しか使わない |
| `REC-08` | 読み出しは時刻範囲で必要な分だけ行い、セッション全件をメモリに載せる処理を設けない | 1 時間の走行で加速度は 18 万件になる |
| `REC-09` | 走行距離は、連続する 2 つの記録位置の haversine 距離を積算して求める | 地球を球とみなす近似で、市街地の走行距離には十分な精度が得られる |

### 2.5 可視化（VIS）

実装は `src/ui/GGDiagram.tsx` ・ `src/ui/g-color.ts` ・ `app/session/[id].tsx` にあります。

| ID | 仕様 | 理由 |
| :-- | :-- | :-- |
| `VIS-01` | G-G ダイアグラムは縦軸の上を前荷重、横軸の右を右荷重とする | ブレーキで上、加速で下、右コーナーで左へ軌跡が伸びる |
| `VIS-02` | 選択点の前後 3 秒の荷重を軌跡として描く | コーナー 1 つ分の荷重の移り変わりが収まる長さ |
| `VIS-03` | 軌跡は古い点ほど薄く、新しい点ほど濃く描き、選択時刻の位置に印を置く | 点ではなく時間の流れとして読めるようにする |
| `VIS-04` | ルートは合計 G（`sqrt(ax² + ay²)` を g 単位にした値）で 5 段階に色分けする。境界は 0.1 / 0.2 / 0.3 / 0.4 g | 日常的な市街地走行から強い減速・旋回までを見分けられる刻み |
| `VIS-05` | 同じ境界を地図の凡例として画面に表示する | 色が何 G を指すのかを読み取れるようにする |
| `VIS-06` | 地図のタップはもっとも近い記録位置を選ぶ。ルートから 100 m を超えて離れている場合は選択しない | 細い折れ線を指で正確に押すのは難しい |

## 4. 受け入れ基準

| ID | 基準 | 関わる仕様 |
| :-- | :-- | :-- |
| `ACP-01` | 較正後、実走行で G の向きが体感と一致する | `CAL` `CRD` |
| `ACP-02` | 走行後、地図上に色分けされたルートが表示される | `VIS-04` `VIS-05` |
| `ACP-03` | コーナーをタップすると、そのコーナーでの G-G 軌跡が見られる | `VIS-01`〜`VIS-03` `VIS-06` |
| `ACP-04` | 過去の走行を一覧から呼び出せる | `REC-01` |
| `ACP-05` | セッションごとと累計の走行時間・距離が表示される | `REC-01` `REC-09` |
