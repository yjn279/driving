## この文書の構成

`npm test` で 3 ファイル・28 件が動きます。対象は `src/core/` の純粋な関数です。

テストは、守っているビジネス要件ごとにまとめています。
[仕様](/developer/specification)のビジネス要件の並びと同じ順に読めます。

| 節 | 守るビジネス要件 | 件数 |
| :-- | :-- | --: |
| 1 | `BR-03` 荷重の向きが体感と一致する | 19 |
| 2 | `BR-01` 荷重の移り変わりを振り返れる | 6 |
| 3 | `BR-07` 走行実績を把握できる | 3 |

「対応システム要件」の列に、そのテストが守っている要件の識別番号を示します。
テストを持たない要件は「4. テストで固定していない要件」にまとめています。

## 1. BR-03 を守る（TST-01〜19）

較正の判定と座標変換です。符号や条件を 1 つ取り違えると記録されるデータ全体が意味を失うため、
テストのうち 19 件がここに集まっています。

`TST-01`〜`TST-15` は `src/core/calibration.test.ts`、`TST-16`〜`TST-19` は
`src/core/vehicle-frame.test.ts` にあります。

| ID | テスト | 何を守るか | 対応システム要件 |
| :-- | :-- | :-- | :-- |
| `TST-01` | ばらつきが閾値以下のサンプルが 2 秒分揃うと静止が成立する | 静止判定が正しく成立する条件 | `SR-03-06` |
| `TST-02` | 2 秒に満たない時点では静止が成立しない | 判定窓を満たさないうちに先へ進まないこと | `SR-03-06` |
| `TST-03` | 途中に大きく外れたサンプルが 1 つ入ると経過がリセットされ、そこから 2 秒分揃うまで成立しない | 停車中でも荷物の積み下ろしなどでセンサーは一瞬乱れる。その直後を「静止」と誤判定しないこと | `SR-03-06` |
| `TST-04` | 平均のノルムが 9.81 ± 0.5 m/s² の範囲を外れると静止が成立しない | 重力以外の力が働いている状態を弾くこと | `SR-03-07` |
| `TST-05` | 重力ベクトルの平均と逆向きの単位ベクトルを返す | `up` の求め方。座標系の起点そのもので、ここが崩れると以降のすべてが意味を失う | `SR-03-04` |
| `TST-06` | 水平成分の平均が閾値以上で向きが安定した状態が判定窓ぶん続くと加速が成立する | 加速判定が正しく成立する条件 | `SR-03-08` `SR-03-09` |
| `TST-07` | 時速 10 km まで 10 m ほど走る緩やかな発進でも成立する | 判定窓 1 秒・閾値 0.5 m/s² が、急発進を求めず穏やかな発進で満たせる大きさであること | `SR-03-08` |
| `TST-08` | 水平成分の平均が閾値に届かない場合は加速が成立しない | 停車中のノイズを「加速」と誤認しないこと | `SR-03-08` |
| `TST-09` | 判定窓に満たない時点では加速が成立しない | 判定窓を満たさないうちに `forward` を確定しないこと | `SR-03-08` |
| `TST-10` | 個々のサンプルが閾値を割っても、ならした値がまっすぐな加速なら成立する | サンプル 1 つずつに閾値を課す実装にすると、まっすぐ加速していても外れ値 1 つで不成立になる。この回帰を防ぐ | `SR-03-10` |
| `TST-11` | ノイズで向きが 1 サンプルごとに振れても、平均の向きが動かなければ成立する | 向きの判定がサンプル単位のノイズに影響されないこと | `SR-03-10` |
| `TST-12` | 曲がりながらの加速のように向きが一方向へ動いていく場合は成立しない | 曲がりながらの発進を「まっすぐ」と誤って確定させないこと | `SR-03-09` |
| `TST-13` | 向きのずれが許容範囲に収まるなら成立する | ずれ 30 度という境界を、`TST-12` と両側から挟んで固定する | `SR-03-09` |
| `TST-14` | 直近の判定窓の水平成分の平均の大きさを返す | 画面に出す数値が、判定に使うのと同じならした値であること。表示と判定がずれると、数値を見て加速しているつもりでも進まない | `SR-03-14` |
| `TST-15` | 判定窓に満たない時点では値を返さない | 根拠のない数値を表示しないこと | `SR-03-14` |
| `TST-16` | 静止時の重力の平均から `up` を求める | 重力の符号の解釈。iOS では画面を上にして水平に置くと z ≈ -9.81 m/s² になる | `SR-03-04` |
| `TST-17` | 加速時のユーザー加速度の平均から `forward` を求める | 水平成分の取り出しと `forward` の向き | `SR-03-03` |
| `TST-18` | `right` は `forward × up` になる | 右手系の向き。ここを取り違えると左右が入れ替わる | `SR-03-03` |
| `TST-19` | 加速の平均が `up` とほぼ平行で水平成分が取れないときは失敗する | 水平成分が取れない状態で `forward` を確定させないこと。確定させると以降の前後左右の区別ができない | `SR-03-11` |

## 2. BR-01 を守る（TST-20〜25）

運転操作と荷重の向きの対応です。`src/core/vehicle-frame.test.ts` にあります。

| ID | テスト | 何を守るか | 対応システム要件 |
| :-- | :-- | :-- | :-- |
| `TST-20` | ブレーキ（後方加速度）で荷重は前を向く | 荷重 = 加速度の逆向き | `SR-01-05` |
| `TST-21` | 加速（前方加速度）で荷重は後ろを向く | 荷重 = 加速度の逆向き | `SR-01-06` |
| `TST-22` | 右コーナー（右方加速度）で荷重は左を向く | 荷重 = 加速度の逆向き。左右の入れ替わりを検出できる唯一のテスト | `SR-01-07` |
| `TST-23` | 端末を傾けて取り付けても、ブレーキで荷重は前を向く | 傾いた取り付けでも符号が保たれること | `SR-01-05` `SR-03-15` |
| `TST-24` | 端末を傾けて取り付けても、加速で荷重は後ろを向く | 同上 | `SR-01-06` `SR-03-15` |
| `TST-25` | 端末を傾けて取り付けても、右コーナーで荷重は左を向く | 同上 | `SR-01-07` `SR-03-15` |

`TST-23`〜`TST-25` は Y 軸 20 度・X 軸 35 度傾けた端末で同じ 3 つを再現しています。
車載ホルダーで端末が水平に固定されることはまれで、傾いた状態でも符号が保たれることこそが本番の条件です。

## 3. BR-07 を守る（TST-26〜28）

走行距離の計算です。`src/core/distance.test.ts` にあります。

| ID | テスト | 何を守るか | 対応システム要件 |
| :-- | :-- | :-- | :-- |
| `TST-26` | 同一地点の距離は 0 になる | 停車中に距離が積み上がらないこと | `SR-07-03` |
| `TST-27` | 経度が同じ（南北方向）2 地点の距離が、球面上の弧の長さ（半径 × 緯度差ラジアン）と 1 m 以内で一致する | 緯度方向の計算が球面の幾何と合うこと | `SR-07-03` |
| `TST-28` | 緯度が同じ（東西方向）2 地点の距離が、緯線に沿った弧の長さ（半径 × cos(緯度) × 経度差ラジアン）と 1 m 以内で一致する | 緯度 60 度を選んでいる。`cos(60°) = 0.5` なので `cos(緯度)` の項が抜けると結果がちょうど 2 倍にずれ、誤差の範囲でごまかせない | `SR-07-03` |
